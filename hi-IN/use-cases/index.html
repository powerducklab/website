देखें, काम कैसे होता है

रोज़ के API काम, कॉन्ट्रैक्ट पर आधारित एक वर्कफ़्लो में।

नीचे कोई काम चुनें। Powerduck आपकी मशीन पर मौजूद OpenAPI फ़ाइल से उसे चलाता है — एनवायरनमेंट, टेस्ट और मॉक सहित। स्थानीय काम के लिए न खाता चाहिए, न अपलोड।

अपना उपयोग चुनें

  1. 01प्रोजेक्ट से दस्तावेज़ बनाएँ।
  2. 02वास्तविक API कॉन्ट्रैक्ट के अनुसार इम्प्लीमेंट करें।
  3. 03पूरा व्यावसायिक परिदृश्य चलाएँ।
  4. 04एक जगह सात प्रोटोकॉल जाँचें।
  5. 05वास्तविक अनुरोध के संदर्भ के साथ जाँचें।
  6. 06एक API से दस्तावेज़ और MCP प्रकाशित करें।
01

प्रोजेक्ट से दस्तावेज़ बनाएँ।

API दस्तावेज़ सही हैं या नहीं, यह जानने के लिए क्या अब भी सोर्स कोड पढ़ना पड़ता है?

POWERDUCK के साथ

अपने कोडिंग एजेंट से MCP के ज़रिए समर्थित प्रोजेक्ट स्कैन करें। API परिभाषा बनाएँ और उसे दस्तावेज़ के रूप में खोलें।

आपको क्या मिलेगा

समीक्षा योग्य API परिभाषा और स्थानीय दस्तावेज़ लिंक।

अपने एजेंट से कहें

इस प्रोजेक्ट को स्कैन करें और मुझे API दस्तावेज़ का लिंक दें।

ध्यान रखने योग्य बातें

केवल समर्थित फ़्रेमवर्क के लिए। अनुमानित फ़ील्ड और स्कैन की चेतावनियाँ जाँचें। स्थानीय लिंक MCP होस्ट पर उसका सत्र चलने तक काम करते हैं।

सेटअप और आवश्यकताएँ देखें ↗
02

वास्तविक API कॉन्ट्रैक्ट के अनुसार इम्प्लीमेंट करें।

क्या AI को स्पेसिफिकेशन देने पर भी अलग फ़ील्ड और पाथ मिलते हैं?

POWERDUCK के साथ

अपना कोडिंग एजेंट Powerduck के MCP से जोड़ें। कोड लिखने से पहले उसे वास्तविक पाथ, स्कीमा और प्रमाणीकरण पढ़ने दें, फिर चल रहे API को जाँचें।

आपको क्या मिलेगा

कॉन्ट्रैक्ट के अनुसार इम्प्लीमेंटेशन, वास्तविक जवाबों से सत्यापित।

अपने एजेंट से कहें

इस API को इसकी परिभाषा के अनुसार इम्प्लीमेंट करें, फिर कॉन्ट्रैक्ट टेस्ट चलाएँ।

ध्यान रखने योग्य बातें

जाँच केवल आपके चलाए गए ऑपरेशन, इनपुट और असर्शन को कवर करती है। इससे बैकएंड के हर व्यवहार का सही होना सिद्ध नहीं होता।

सेटअप और आवश्यकताएँ देखें ↗
03

पूरा व्यावसायिक परिदृश्य चलाएँ।

क्या हर API बदलाव के बाद वही व्यावसायिक प्रक्रिया हाथ से दोहराते हैं?

POWERDUCK के साथ

साइन इन → ऑर्डर बनाएँ → ऑर्डर प्राप्त करें जैसी प्रक्रिया बताएँ। AI को परिदृश्य बनाने, चरणों के बीच मान भेजने और टेस्ट चलाने दें।

आपको क्या मिलेगा

हर चरण के परिणाम और विफल असर्शन — सिर्फ़ बनाई गई टेस्ट स्क्रिप्ट नहीं।

अपने एजेंट से कहें

साइन इन → ऑर्डर बनाएँ → ऑर्डर प्राप्त करें का टेस्ट करें। बताएँ कौन-सा चरण विफल होता है।

ध्यान रखने योग्य बातें

जाँच केवल आपके चलाए गए ऑपरेशन, इनपुट और असर्शन को कवर करती है। इससे बैकएंड के हर व्यवहार का सही होना सिद्ध नहीं होता।

सेटअप और आवश्यकताएँ देखें ↗
04

एक जगह सात प्रोटोकॉल जाँचें।

क्या अगले एंडपॉइंट का प्रोटोकॉल अलग होने पर टूल बदलना पड़ता है?

POWERDUCK के साथ

HTTP, GraphQL, WebSocket, SSE, gRPC, MCP और A2A डीबग करें। एक ही कार्यक्षेत्र में जवाब, स्ट्रीम और टूल कॉल जाँचें।

आपको क्या मिलेगा

ठीक-ठीक क्या हुआ, यह देखने के लिए मैन्युअल नियंत्रण।

ध्यान रखने योग्य बातें

डेस्कटॉप और ब्राउज़र में प्रोटोकॉल समर्थन अलग है। gRPC जैसे नेटिव ट्रांसपोर्ट के लिए डेस्कटॉप ऐप इस्तेमाल करें।

सेटअप और आवश्यकताएँ देखें ↗
05

वास्तविक अनुरोध के संदर्भ के साथ जाँचें।

क्या AI की मदद लेने के लिए हर बार अनुरोध और जवाब चैट में कॉपी करते हैं?

POWERDUCK के साथ

सहायक को संबंधित API संदर्भ दें। उससे अनुरोध भेजने, जवाब जाँचने और विफलता का कारण खोजने में मदद माँगें।

आपको क्या मिलेगा

अनुरोध के परिणामों पर आधारित निदान और समीक्षा योग्य बदलाव।

अपने एजेंट से कहें

जाँचें कि यह अनुरोध क्यों विफल हो रहा है। सुधार सुझाने से पहले जवाब देखें।

ध्यान रखने योग्य बातें

AI सुविधाओं के लिए कॉन्फ़िगर किया हुआ मॉडल चाहिए। रिमोट प्रदाता को भेजा गया संदर्भ आपके डिवाइस से बाहर जाता है; मैन्युअल संपादन के लिए AI ज़रूरी नहीं।

सेटअप और आवश्यकताएँ देखें ↗
06

एक API से दस्तावेज़ और MCP प्रकाशित करें।

क्या सिर्फ़ API दस्तावेज़ और MCP साझा करने के लिए अलग होस्टिंग सँभालते हैं?

POWERDUCK के साथ

अपने API का एक संस्करण Powerduck Cloud पर प्रकाशित करें। लोगों को पढ़ने योग्य दस्तावेज़ और AI क्लाइंट को MCP एंडपॉइंट दें।

आपको क्या मिलेगा

होस्ट किए गए दस्तावेज़ और MCP URL, बिना खुद होस्टिंग व्यवस्था चलाए।

ध्यान रखने योग्य बातें

क्लाउड होस्टिंग आपके खाते के कोटे का इस्तेमाल करती है। अपलोड की गई API परिभाषा में उदाहरण या आंतरिक जानकारी हो सकती है; साझा करने से पहले जाँचें।

सेटअप और आवश्यकताएँ देखें ↗

पहले एक API पर आज़माएँ।

अपना कोई मौजूदा स्पेसिफिकेशन खोलें या अंतर्निहित उदाहरण से शुरू करें। अपना प्रोजेक्ट जोड़ने से पहले वर्कफ़्लो समझें।
