POWERDUCK HUB

एक OpenAPI स्पेसिफिकेशन। स्थानीय डेवलपमेंट। ऑनलाइन साझा करना।

API का काम डेस्कटॉप ऐप में करें। दस्तावेज़ साझा करने और AI टूल को अपने API से जोड़ने के लिए Hub इस्तेमाल करें।

  1. 01

    बनाएँ और जाँचें

    Powerduck में अपना API डिज़ाइन, डीबग और टेस्ट करें।

  2. 02

    OpenAPI से प्रकाशित करें

    अपने स्पेसिफिकेशन से होस्ट किए गए दस्तावेज़ और MCP एंडपॉइंट बनाएँ।

  3. 03

    साझा करें और जोड़ें

    दस्तावेज़ का लिंक साझा करें, MCP क्लाइंट जोड़ें और तय करें कि प्रोजेक्ट को सार्वजनिक सूची में दिखाना है या नहीं।

Hub पर मुफ़्त प्रकाशित करेंHub देखें

प्लान की सीमाओं के भीतर मुफ़्त होस्टिंग। आपका व्यावसायिक API आपके अपने बैकएंड पर चलता रहता है।

Powerduck क्यों

कई API टूल की जगह एक स्थानीय फ़ाइल।

रिपॉज़िटरी की एक OpenAPI YAML फ़ाइल से डिज़ाइन, डीबगिंग, टेस्ट, मॉक, दस्तावेज़ और MCP चलते हैं। आपके कोडिंग एजेंट भी वही फ़ाइल इस्तेमाल करते हैं।

एक फ़ाइल से सभी सुविधाएँ

उसी OpenAPI स्पेसिफिकेशन से डिज़ाइन, डीबगिंग, टेस्ट, मॉक, दस्तावेज़ और MCP उपलब्ध कराएँ, ताकि अलग-अलग परिभाषाओं में अंतर न आए।

अन्य टूल कलेक्शन, दस्तावेज़, मॉक और टेस्ट के लिए अलग फ़ाइलें
Powerduck एक YAML से हर टूल और आपके एजेंट चलते हैं

हर जवाब का कॉन्ट्रैक्ट सत्यापन

हर जवाब केवल दिखाया नहीं जाता, बल्कि OpenAPI स्पेसिफिकेशन से जाँचा भी जाता है — गलत टाइप या पाथ तुरंत पकड़ में आता है।

देखें, काम कैसे होता है

रोज़ के API काम, कॉन्ट्रैक्ट पर आधारित एक वर्कफ़्लो में।

नीचे कोई काम चुनें। Powerduck आपकी मशीन पर मौजूद OpenAPI फ़ाइल से उसे चलाता है — एनवायरनमेंट, टेस्ट और मॉक सहित। स्थानीय काम के लिए न खाता चाहिए, न अपलोड।

स्थानीय कार्यक्षेत्र का मतलब सीमित सुविधाएँ नहीं होना चाहिए।

खाते या अपलोड के बिना अपना स्थानीय API कार्यक्षेत्र शुरू करें। अपने अनुरोध, प्रमाणीकरण, एनवायरनमेंट और असर्शन साथ लाएँ। ऑनलाइन प्रकाशित करना हो तो क्लाउड चुनें।

अपनी मशीन पर शुरू करें

डाउनलोड करें। अपने काम पर ध्यान दें।

Powerduck एक डेस्कटॉप API कार्यक्षेत्र है। स्थानीय फ़ाइल खोलें, पहला अनुरोध भेजें और जब चाहें अपना कोडिंग एजेंट जोड़ें। शुरुआत के लिए खाते की ज़रूरत नहीं है।

मुख्य कार्यक्षेत्र

API का काम यहीं पूरा करें।

स्थानीय फ़ाइलों, कोड स्कैनिंग और नेटिव प्रोटोकॉल डीबगिंग के लिए डेस्कटॉप ऐप इस्तेमाल करें। डिज़ाइन, जाँच या टेस्ट में मदद चाहिए तो अपना चुना हुआ AI मॉडल जोड़ें।

  1. 1 ऐप डाउनलोड करें और स्थानीय उदाहरण आज़माएँ — न खाता चाहिए, न मॉडल कुंजी।
  2. 2 अपनी OpenAPI फ़ाइल खोलें या मौजूदा कोडबेस स्कैन करें।
  3. 3 कोडिंग एजेंट जोड़ें, कोड बदलें और वास्तविक बैकएंड को कॉन्ट्रैक्ट से मिलाकर जाँचें।

OpenAPI स्पेसिफिकेशन एडिटर

OpenAPI स्पेसिफिकेशन एडिटर

रूपरेखा स्पेसिफिकेशन की वास्तविक संरचना पर आधारित है, इंडेंटेशन के अनुमान पर नहीं। पाथ और कॉम्पोनेंट को ट्री में देखें और त्रुटियाँ जहाँ हैं, वहीं ठीक करें।

  • स्कीमा के अनुसार सत्यापन। फ़ाइल में घोषित 3.0, 3.1 या 3.2 संस्करण के अनुसार जाँच करें।
  • हल किए गए $ref पर नेविगेशन। परिभाषाओं पर जाएँ, उनके उपयोग देखें और गलत लिखे संदर्भों के लिए सुझाव पाएँ।
  • सीधे फ़ाइल में संपादन। आपकी रिपॉज़िटरी ही प्रामाणिक स्रोत रहती है।
  • नियमों के नाम सहित समस्याएँ। CI की विफलताएँ और एडिटर के निदान एक ही शब्दावली इस्तेमाल करते हैं।

API डीबगिंग

स्पेसिफिकेशन के अनुसार API डीबगिंग

परिचित टूल जैसा अनुरोध बिल्डर, साथ में एक अतिरिक्त क्षमता: हर जवाब को कॉन्ट्रैक्ट के अनुसार जाँचना।

  • पाथ और टैग से तैयार कलेक्शन। न इम्पोर्ट का अलग चरण, न हाथ से दोबारा सिंक करना।
  • हर जवाब पर कॉन्ट्रैक्ट की जाँच। अघोषित प्रॉपर्टी, गायब फ़ील्ड और बदले हुए टाइप तुरंत पहचानें।
  • एनवायरनमेंट और वेरिएबल। मौजूदा डेवलपमेंट और स्टेजिंग कॉन्फ़िगरेशन दोबारा इस्तेमाल करें।
  • securitySchemes से सुरक्षा सेटिंग। Bearer, API कुंजी और OAuth का कॉन्फ़िगरेशन स्पेसिफिकेशन से शुरू होता है।

MCP सर्वर जनरेटर

OpenAPI से MCP सर्वर बनाएँ

आपका स्पेसिफिकेशन पहले से टूल की परिभाषा है। Powerduck उससे चलने योग्य MCP सर्वर बनाता है और दिखाता है कि हर टूल किन OpenAPI फ़ील्ड से बना है।

  • हर टूल का स्रोत स्पष्ट। हर टूल को उसके ऑपरेशन, operationId और स्कीमा तक खोजा जा सकता है।
  • अपूर्ण और छोड़े गए टूल की स्थिति। अधूरे मेटाडेटा से चुपचाप कमज़ोर टूल बनाने के बजाय उनकी कमी दिखाई जाती है।
  • सहेजते ही दोबारा तैयार। स्पेसिफिकेशन बदलें और बिना अलग बिल्ड चरण के टूल अपडेट पाएँ।
  • स्थानीय ट्रांसपोर्ट। स्थानीय एजेंट और वर्कफ़्लो के लिए stdio या HTTP से चलाएँ।

API दस्तावेज़ जनरेटर

उसी कॉन्ट्रैक्ट से API दस्तावेज़

अपने OpenAPI मॉडल से सीधे संदर्भ दस्तावेज़ बनाएँ, उन्हें स्टैटिक फ़ाइलों में एक्सपोर्ट करें और कहीं भी होस्ट करें।

  • स्कीमा से पैरामीटर तालिकाएँ। ज़रूरी फ़ील्ड, enum और विवरण एक-दूसरे के अनुरूप रहते हैं।
  • कई भाषाओं में उदाहरण। ऑपरेशन से cURL, Node, Python और Go के उदाहरण बनाएँ।
  • वास्तविक कॉन्ट्रैक्ट से जवाब। सफलता और त्रुटि के जवाब उन्हीं ऑब्जेक्ट से आते हैं जिन्हें डीबगर जाँचता है।
  • स्टैटिक एक्सपोर्ट। न रनटाइम निर्भरता, न किसी दस्तावेज़ प्लेटफ़ॉर्म में बँधने की मजबूरी।

निजता नीति

स्थानीय उपयोग के लिए क्लाउड खरीदना ज़रूरी नहीं है। मुफ़्त उपयोग में दो स्पेसिफिकेशन शामिल हैं; स्वीकृत शेयरिंग पुरस्कारों से यह सीमा बढ़ सकती है। डेस्कटॉप लाइसेंस यह सीमा हटा देता है। अपनी कुंजी से किए गए मॉडल उपयोग का बिल आपका प्रदाता देता है; होस्ट किए गए मॉडल क्रेडिट और क्लाउड होस्टिंग अलग हैं।

डेवलपर सबसे पहले क्या जानना चाहते हैं

स्थानीय फ़ाइलों, OpenAPI संस्करणों, MCP बनाने और लाइसेंस के बारे में उपयोगी जानकारी।

क्या Powerduck मेरा OpenAPI स्पेसिफिकेशन कहीं अपलोड करता है?

स्थानीय फ़ाइलों के लिए खाते की ज़रूरत नहीं है। रिमोट AI आपके चुने हुए प्रदाता को संबंधित संदर्भ भेजता है। क्लाउड पर प्रकाशन करने पर आपकी चुनी हुई सामग्री अपलोड होती है। वैकल्पिक उपयोग आँकड़े डिफ़ॉल्ट रूप से बंद हैं; फ़ील्ड और नियंत्रण के लिए निजता नीति देखें।

OpenAPI के कौन-से संस्करण समर्थित हैं?

OpenAPI 3.0, 3.1 और 3.2। Powerduck फ़ाइल में घोषित संस्करण पहचानकर उसी के नियमों से जाँचता है, सभी संस्करणों के लिए एक सीमित साझा नियम-समूह से नहीं।

MCP सर्वर कैसे बनता है?

operationId वाले ऑपरेशन MCP टूल बनते हैं। आर्ग्युमेंट पैरामीटर और requestBody स्कीमा से लिए जाते हैं। कॉम्पोनेंट स्कीमा संसाधन के रूप में उपलब्ध कराए जा सकते हैं। स्पेसिफिकेशन बदलते ही जनरेट किया गया सर्वर अपडेट होता है।

क्या डेस्कटॉप लाइसेंस एक सदस्यता है?

नहीं। Powerduck Desktop का स्थायी लाइसेंस एक बार खरीदा जाता है। उसी प्रमुख संस्करण के अपडेट शामिल हैं। आगे के प्रमुख संस्करण में अपग्रेड करना वैकल्पिक है।

क्या मैं Postman कलेक्शन इस्तेमाल करता रह सकता हूँ?

हाँ। मौजूदा कलेक्शन और एनवायरनमेंट इस्तेमाल किए जा सकते हैं। Powerduck OpenAPI स्पेसिफिकेशन को प्रामाणिक कॉन्ट्रैक्ट मानता है और उससे अलग हो रहे अनुरोधों को पहचानने में मदद करता है।

क्या यह CI में काम करता है?

हाँ। वही सत्यापन और जनरेशन इंजन उपलब्ध है @powerduck/openapi-cli के ज़रिए। यह CI के लिए तैयार कमांड-लाइन टूल पुल रिक्वेस्ट और स्वचालित पाइपलाइन में चलता है। यह छह प्रोटोकॉल (HTTP, SSE, WebSocket, gRPC, MCP, GraphQL) पर बैच टेस्ट, कॉन्फ़िगर करने योग्य समांतर निष्पादन और CI एकीकरण के लिए JUnit-संगत रिपोर्ट देता है।
