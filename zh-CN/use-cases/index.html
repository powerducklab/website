代码审阅 · 文档
01

接口改了，文档不用再维护一遍。

POWERDUCK 的解法

在编程助手里连接 Powerduck MCP，扫描已适配框架的项目，生成接口定义并打开文档。

你得到的结果

从支持的项目中提取接口定义，检查生成的 OpenAPI，并在本地预览文档。

可以直接这样说

扫描这个项目，生成 API 文档，给我一个可以打开的链接。

使用前了解

仅支持已适配的框架，请检查推断字段和扫描提示。本机链接在 MCP 所在电脑上访问，会话结束后失效。

02

让 Agent 读取接口事实，少一次反复解释。

POWERDUCK 的解法

让编程助手通过 MCP 读取真实的路径、数据结构与鉴权要求，再按定义实现，最后对运行中的接口做验证。

你得到的结果

通过开发者 MCP 向编程助手提供接口定义，并验证实际响应是否符合契约。

可以直接这样说

根据这份 API 定义实现接口，再运行契约测试，检查是否一致。

使用前了解

检查范围取决于实际运行的接口、输入和断言，不代表后端所有行为都已验证。

04

切换协议，不必再换一套工具。

POWERDUCK 的解法

HTTP、GraphQL、WebSocket、SSE、gRPC、MCP、A2A，在同一工作区查看响应、消息流和工具调用。

你得到的结果

使用对应协议的调试工具，检查请求、响应和连接状态。

使用前了解

桌面版和网页版支持范围不同。gRPC 等原生传输请使用桌面版。

05

排查失败请求，不必反复复制上下文。

POWERDUCK 的解法

给助手相关接口上下文，让它发送请求、查看返回，结合实际结果定位问题，提出可审阅的修改建议。

你得到的结果

将请求与响应作为 AI 分析上下文，检查建议并继续验证。

可以直接这样说

帮我查这个请求为什么失败，先看响应，再给修改建议。

使用前了解

使用 Google 或 GitHub 登录。产品仅提供内置模型，不提供模型选择、自带密钥或自定义端点。只有请求 AI 工作时才向托管模型服务发送所选代码上下文。本地扫描排除常见依赖、构建和凭据路径，但不能保证源码中没有秘密信息，请核对分享范围。

查看操作步骤 ↗
06

分享 API，不必再维护一套文档服务。

POWERDUCK 的解法

将一个 API 版本发布到 Powerduck Cloud：给人看文档，给 AI 客户端连 MCP。

你得到的结果

从 OpenAPI 发布托管文档与 MCP 端点；业务接口继续运行在你的后端。

使用前了解

Cloud 托管受账户额度限制。接口定义可能包含示例或内部信息，分享前请检查内容。

打开已有的接口定义，或者使用内置示例。先跑通流程，再接入自己的项目。
