01

프로젝트에서 문서를 생성하세요.

API 문서가 맞는지 확인하려고 아직도 소스 코드를 읽고 계신가요?

POWERDUCK과 함께

코딩 에이전트가 MCP를 통해 지원되는 프로젝트를 스캔합니다. API 정의를 생성하고 문서로 열어보세요.

얻을 수 있는 결과

검토 가능한 API 정의와 로컬 문서 링크.

에이전트에 요청하세요

이 프로젝트를 스캔해서 API 문서 링크를 만들어 줘.

알아두세요

지원되는 프레임워크에서만 사용할 수 있습니다. 추론된 필드와 스캔 경고를 검토하세요. 로컬 링크는 MCP 세션이 실행 중인 동안 해당 호스트에서 작동합니다.

03

업무 시나리오 전체를 실행하세요.

API가 바뀔 때마다 같은 업무 흐름을 수동으로 반복하시나요?

POWERDUCK과 함께

로그인 → 주문 생성 → 주문 조회 같은 흐름을 설명하세요. AI가 시나리오를 구성하고 단계 간에 값을 전달하며 테스트를 실행합니다.

얻을 수 있는 결과

에이전트에 요청하세요

로그인 → 주문 생성 → 주문 조회를 테스트하고 어느 단계에서 실패하는지 알려 줘.

알아두세요

실행한 작업, 입력, 어서션만 검사합니다. 백엔드의 모든 동작이 올바르다는 것을 보장하지는 않습니다.

04

7개 프로토콜을 한곳에서 살펴보세요.

다음 엔드포인트의 프로토콜이 다르다는 이유로 도구를 바꾸시나요?

POWERDUCK과 함께

HTTP, GraphQL, WebSocket, SSE, gRPC, MCP, A2A를 디버깅하세요. 같은 작업 공간에서 응답, 스트림, 도구 호출을 확인할 수 있습니다.

얻을 수 있는 결과

정확히 무슨 일이 있었는지 직접 살펴볼 수 있는 수동 제어.

알아두세요

데스크톱과 브라우저의 프로토콜 지원 범위가 다릅니다. gRPC 같은 네이티브 전송 방식에는 데스크톱 앱을 사용하세요.

05

실제 요청 컨텍스트로 원인을 조사하세요.

AI의 도움이 필요할 때마다 요청과 응답을 채팅에 복사하시나요?

POWERDUCK과 함께

어시스턴트에 관련 API 컨텍스트를 제공하세요. 요청을 보내고 응답을 살펴보며 실패 원인을 좁혀 달라고 요청할 수 있습니다.

얻을 수 있는 결과

실제 요청 결과에 근거한 진단과 검토 가능한 변경 사항.

에이전트에 요청하세요

이 요청이 실패하는 이유를 조사해 줘. 수정안을 제안하기 전에 응답부터 확인해 줘.

알아두세요

AI 기능을 사용하려면 모델을 설정해야 합니다. 원격 공급자에게 보내는 컨텍스트는 기기를 벗어납니다. 수동 편집에는 AI가 필요하지 않습니다.

하나의 API에서 문서와 MCP를 게시하세요.

API 문서와 MCP를 공유하려고 별도 호스팅 환경을 관리하시나요?

POWERDUCK과 함께

API의 한 버전을 Powerduck Cloud에 게시하세요. 사람에게는 읽기 쉬운 문서를, AI 클라이언트에는 MCP 엔드포인트를 제공할 수 있습니다.

얻을 수 있는 결과

알아두세요

Cloud 호스팅에는 계정 할당량이 적용됩니다. 업로드하는 API 정의에 예제나 내부 정보가 포함될 수 있으니 공유 전에 검토하세요.
