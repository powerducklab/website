API 디버깅

명세를 기준으로 API 디버깅

개발자에게 익숙한 요청 작성 도구에 계약 기반 응답 검증을 더했습니다.

  • 경로와 태그로 컬렉션 자동 구성 별도로 가져오거나 수동으로 다시 동기화할 필요가 없습니다.
  • 모든 응답의 계약 검사 선언되지 않은 속성, 누락된 필드, 타입 불일치를 응답에서 바로 확인하세요.
  • 환경과 변수 기존 개발 및 스테이징 설정을 재사용하세요.
  • securitySchemes 기반 인증 설정 명세를 바탕으로 Bearer, API 키, OAuth 인증을 설정합니다.

MCP 서버 생성기

OpenAPI로 MCP 서버 생성

명세에는 이미 도구를 정의할 정보가 담겨 있습니다. Powerduck은 이를 실행 가능한 MCP 서버로 변환하고, 각 도구가 어떤 OpenAPI 필드에서 만들어졌는지 보여줍니다.

  • 명확한 출처 모든 도구에서 원본 작업, operationId, 스키마를 추적할 수 있습니다.
  • 제한되거나 건너뛴 항목 표시 메타데이터가 부족하면 불완전한 도구를 조용히 생성하는 대신 부족한 내용을 표시합니다.
  • 저장 시 다시 생성 명세를 변경하면 별도 빌드 없이 도구가 갱신됩니다.
  • 로컬 전송 방식 로컬 에이전트와 워크플로에서 stdio 또는 HTTP로 실행하세요.

개발자가 먼저 궁금해하는 것들

로컬 파일, OpenAPI 버전, MCP 생성, 라이선스에 관한 안내입니다.

Powerduck이 제 OpenAPI 명세를 업로드하나요?

Your project remains local. AI requests send selected source context to Powerduck’s managed model providers. Publishing documentation is a separate action you choose.

어떤 OpenAPI 버전을 지원하나요?

OpenAPI 3.0, 3.1, 3.2를 지원합니다. 공통 기능만으로 검증하지 않고 파일에 선언된 버전을 감지해 해당 규격으로 검증합니다.

MCP 서버는 어떻게 생성되나요?

operationId가 있는 작업이 MCP 도구가 됩니다. 매개변수와 requestBody 스키마에서 인수를 생성합니다. 컴포넌트 스키마를 리소스로 제공할 수도 있습니다. 명세가 변경될 때마다 생성된 서버가 갱신됩니다.

How do subscriptions and credit resets work?

Powerduck uses monthly subscriptions. Free credits reset daily; paid credits reset every seven days.

기존 Postman 컬렉션을 계속 사용할 수 있나요?

네. 기존 컬렉션과 환경을 계속 사용할 수 있습니다. Powerduck은 OpenAPI 명세를 기준 계약으로 삼고 요청이 계약과 다른 부분을 찾아줍니다.

CI에서도 사용할 수 있나요?

네. 동일한 검증 및 생성 엔진을 제공하는 @powerduck/openapi-cli 명령줄 도구를 풀 리퀘스트와 자동화 파이프라인에서 실행할 수 있습니다. 6개 프로토콜(HTTP, SSE, WebSocket, gRPC, MCP, GraphQL)의 일괄 테스트, 동시 실행 수 설정, CI 연동용 JUnit 호환 보고서를 지원합니다.
