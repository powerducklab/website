OpenAPI 規格編輯器

OpenAPI 規格編輯器

大綱根據規格的實際結構產生，不靠縮排推測。以樹狀結構瀏覽路徑和元件，直接在問題所在處修正。

  • 基於 Schema 的驗證。 依照檔案宣告的 3.0、3.1 或 3.2 方言進行驗證。
  • 解析 $ref 並導覽。 跳至到定義、查看引用，並獲得拼寫錯誤引用的建議。
  • 就地編輯。 你的儲存庫始終是唯一事實來源。
  • 以規則名稱標示問題。 CI 報錯和編輯器診斷使用同一套詞彙。

API偵錯

基於規格偵錯 API

請求介面沿用開發者熟悉的工具形態，再加上那些工具預設做不到的一件事：對照契約驗證回應。

  • 按路徑和標籤自動生成集合。 無需匯入，也不用手動重新同步。
  • 每次回應都做契約檢查。 直接標示未宣告的屬性、缺少的欄位與型別差異。
  • 環境與變數。 重用既有的開發與預備環境設定。
  • 從 securitySchemes 取得安全性設定。 Bearer、API Key 和 OAuth 設定都從規格開始。

MCP 伺服器生成器

從 OpenAPI 生成 MCP 伺服器

你的規格本身就是一份工具清單。Powerduck 把它編譯成可執行的 MCP 伺服器，並清楚展示每個工具來自哪些 OpenAPI 欄位。

  • 來源可見。 每個工具都能追溯到它的 operation、operationId 和 schema。
  • 清楚標示功能受限與略過的狀態。 缺失的中繼資料會明確顯示，而不是悄悄生成能力薄弱的工具。
  • 儲存後立即重新產生。 修改規格後，工具會隨之更新，不需要額外的建置步驟。
  • 本機傳輸方式。 透過 stdio 或 HTTP 執行，服務本機助手與工作流。

支援哪些 OpenAPI 版本？

支援 OpenAPI 3.0、3.1 和 3.2。Powerduck 會偵測宣告的版本，依照對應方言驗證，而非將所有版本限制在共通功能範圍內。

MCP 伺服器是怎麼生成的？

帶有 operationId 的操作會轉成 MCP 工具，參數則由 parameters 與 requestBody 的結構描述推導而來。元件的結構描述可公開為資源。規格變更時，產生的伺服器也會更新。

桌面授權是訂閱制嗎？

不是。Powerduck 桌面版採一次購買、永久授權，同一主要版本的更新均包含在內。未來是否升級至新的主要版本，由你自行決定。

我還能繼續用 Postman 集合嗎？

可以。已有的集合和環境都能繼續使用。Powerduck 把 OpenAPI 規格當作權威契約，並幫你找出請求與契約的偏差。

能用在 CI 裡嗎？

可以。同一套驗證和生成引擎透過 @powerduck/openapi-cli 提供。這套命令列工具可在 Pull Request 與 CI 自動化管線中執行，支援六種通訊協定（HTTP、SSE、WebSocket、gRPC、MCP、GraphQL）的批次測試、可設定的並行數，以及相容 JUnit 的報告。
