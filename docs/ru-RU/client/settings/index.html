Настройки

Настройки настольного клиента определяют внешний вид приложения и отправку запросов. Параметры приложения отделены от изменений документа API, поэтому смена темы или настройка прокси не меняют контракт.

Внешний вид​

  • Тема — переключение между светлой и тёмной (theme.get, theme.set). Выбор применяется ко всему приложению и сохраняется.
  • Язык интерфейса — выберите один из шестнадцати языков или автоматическое определение по системе:

Поведение запросов​

Эти настройки управляют исходящими запросами из рабочей области и сценариев:

  • Тайм-аут запроса (requestTimeoutMs) — в миллисекундах; 0 означает отсутствие ограничения;
  • Строгий SSL (strictSSL) — проверка сертификатов TLS; отключение позволяет работать с самоподписанными или недоверенными сертификатами;
  • Следовать перенаправлениям (followRedirects) и максимум перенаправлений (maxRedirects);
  • Версия HTTP (protocolVersion) — http1, http2 или auto;
  • Отключить cookie (disableCookies) — отключение обработки cookie для запросов.

Прокси​

Выберите режим исходящего прокси (off, system или custom):

  • off — без прокси;
  • system — использовать прокси операционной системы;
  • custom — задать URL прокси, при необходимости имя пользователя, пароль и список исключений.

Список исключений принимает хосты и шаблоны, например localhost,127.0.0.1 и имена с подстановочными знаками. Пароли прокси можно записать, но нельзя прочитать обратно; пустое значение удаляет пароль.

TLS и клиентские сертификаты​

Для окружений с собственной цепочкой доверия или взаимным TLS:

  • Собственный CA — включите сертификат центра сертификации и укажите путь к нему, чтобы доверять внутреннему или самоподписанному корневому сертификату;
  • Клиентские сертификаты (mTLS) — задайте для хоста пару сертификат/ключ либо файл PFX, при необходимости с паролем. Область применения ограничивается хостом и портом.

Сертификаты можно добавлять, удалять по ID или очищать полностью. Пароли сертификатов доступны только для записи и не возвращаются.

Встроенный терминал​

Внизу приложения есть панель терминала:

  • terminal.open открывает панель; передайте {"cwd":"document"}, чтобы открыть её в папке активного документа, которую приложение преобразует в реальный абсолютный путь;
  • terminal.run вводит и запускает одну явно указанную команду оболочки после подтверждения в карточке.

Команды выполняются только по вашей явной просьбе; открытие панели ничего не запускает.

Действия с файлами и системой​

  • shell.revealFile — показать активный документ или указанный путь в системном файловом менеджере;
  • shell.openPath — открыть документ приложением по умолчанию;
  • shell.openExternal — открыть стороннюю внешнюю страницу в системном браузере.

Официальные страницы Powerduck используют специальный инструмент ссылок (app.officialLink), который показывает карточку в чате, не покидая приложение.

Примеры клиентского кода​

Для любой операции ассистент может создать готовый клиентский код (clientcode.generate) и показать его в карточке с выбором языка и клиентской библиотеки. Поддерживаются C, C#, Go, Java, JavaScript, Node, Kotlin, PHP, Python, Ruby, Rust, shell, Swift и другие языки. Код показывается в карточке, а не вставляется в чат.

Изменение настроек через ассистента​

Запросы на уровне приложения — смена темы или языка, настройка прокси, игнорирование ошибки сертификата, выбор версии HTTP — обрабатываются инструментами настроек, а не как задачи проектирования API. Изменения требуют подтверждения перед применением.
