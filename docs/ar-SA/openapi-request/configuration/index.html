الإعدادات

تنقسم الإعدادات إلى ثلاث طبقات: خيارات دوال إنشاء العميل أو مصحح الأخطاء، وكائن SendOptions الممرَّر إلى prepare() وsend()، والخيارات الخاصة بكل بروتوكول.

خيارات دوال الإنشاء​

CreateClientOptions​

تُمرَّر إلى createClient(options?). جميع الحقول اختيارية.

الحقلالنوعالوصف
writeBackWriteBackOptionsالتحكم في كيفية دمج الاستجابات في المواصفة
responseToResponseOptionsالتحكم في كيفية توحيد بنية كائنات الاستجابة
import { createClient } from "@powerduck/openapi-request";

const client = createClient({
  writeBack: {
    overwriteExamples: true,
    // ... other WriteBackOptions
  },
  response: {
    includeExamples: false,
    // ... other ToResponseOptions
  },
});

DebuggerOptions​

تُمرَّر إلى createDebugger(config?). جميع الحقول اختيارية.

الحقلالنوعالوصف
adaptersProtocolAdapter[]قائمة محولات مخصصة تستبدل جميع المحولات الافتراضية
extraAdaptersProtocolAdapter[]محولات إضافية تُضاف إلى السجل الافتراضي
writeBackWriteBackOptionsخيارات الكتابة في المواصفة
responseToResponseOptionsخيارات توحيد بنية الاستجابة
writeBackTruncatedbooleanكتابة المخطط المستنتج من التدفقات المبتورة في المواصفة؛ القيمة الافتراضية: true
import { createDebugger, HttpAdapter, WebSocketAdapter } from "@powerduck/openapi-request";

// Use only HTTP and WebSocket adapters
const debugger1 = createDebugger({
  adapters: [new HttpAdapter(), new WebSocketAdapter()],
});

// Add a custom adapter to the defaults
const debugger2 = createDebugger({
  extraAdapters: [new MyCustomAdapter()],
  writeBackTruncated: true,
});

الكتابة في المواصفة والأمثلة الملتقطة​

يدعم WriteBackOptions الخيارات strategy (إما "merge" أو "replace"، والافتراضي "merge")، وkeepExistingDescription (الافتراضي true)، وallowedStatusCodes (القيمة الفارغة تعني جميع الرموز)، وprotectComponentRefs (الافتراضي true)، وoverwriteExamples (الافتراضي true)، وrequirePassingTests. يطبق مسار الإرسال شرط اجتياز الاختبارات، أما استدعاء writeBackResponse مباشرة فلا يطبقه.

يدعم ToResponseOptions الخيارات includeExamples (الافتراضي true)، وmaxExampleChars (الافتراضي 4000)، وmaxEventPreviewChars (الافتراضي 200). عطّل التقاط الأمثلة أو راجعها قبل النشر، فقد تتضمن الاستجابات الفعلية بيانات اعتماد أو بيانات شخصية.

يعيد مسار الإرسال عادةً نسخة معدلة في patchedSpec؛ ولا يعدّل مستند الإدخال أو يحفظ ملفًا. اضبط writeBack: false لكل استدعاء تريد فيه تجاوز هذه الخطوة. يحدد كائن writeBack في دالة الإنشاء كيفية الدمج، بينما تتيح القيمة المنطقية الخاصة بكل استدعاء تفعيل الكتابة أو تعطيلها.

SendOptions​

كائن الإدخال الرئيسي للدالتين prepare() وsend(). تُمرَّر من خلاله المواصفة والهدف والقيم وجميع إعدادات الطلب.

الحقلالنوعمطلوبالوصف
specOpenApiDocumentنعممستند OpenAPI 3.2 كامل
targetOperationTargetنعممعرّف العملية؛ انظر أدناه
valuesRequestValuesلاالقيم الفعلية للمسار والاستعلام والترويسات وملفات تعريف الارتباط والمحتوى
serverUrlstringلايتجاوز spec.servers[0].url
serverVariablesRecord<string, string>لامتغيرات قالب عنوان URL للخادم
variablesRecord<string, string>لامتغيرات البيئة المشار إليها بصيغة {{name}}
globalsRecord<string, string>لامتغيرات عامة بأسلوب Postman
localVariablesRecord<string, string>لامتغيرات محلية
collectionVariablesRecord<string, string>لامتغيرات على مستوى المجموعة
authAuthConfigلاإعدادات المصادقة
scriptsScriptConfigلاالبرامج النصية السابقة للطلب وبرامج الاختبار
runnerRuntimeRunOptionsلاتمرير جميع خيارات postman-runtime مباشرةً، بأعلى أولوية
websocketWebSocketOptionsلاخيارات خاصة بـ WebSocket
graphqlGraphQLOptionsلاخيارات خاصة بـ GraphQL
mcpMcpOptionsلاخيارات خاصة بـ MCP
grpcanyلاخيارات خاصة بـ gRPC
timeoutnumberلامهلة كل طلب بالمللي ثانية؛ اختصار للإعداد runner.timeout.request

يقبل SendOptions أيضًا خيارات التحكم التالية للتنفيذ والتدفق:

الحقلالنوعالوصف
fetchtypeof fetchوسيلة نقل fetch معزولة يوفرها التطبيق المضيف حيث تكون مدعومة؛ يظل HTTP/SSE معتمدًا على postman-runtime.
writeBackbooleanاضبطه على false لإبقاء patchedSpec غير معرّف مع الاستمرار في إنشاء responseFragment.
signalAbortSignalإلغاء التنفيذ أو أخذ العينات؛ قد تُعاد نتيجة جزئية مع ذلك.
maxEventsnumberالحد الأقصى لعدد أحداث التدفق المحتفظ بها.
maxStreamMsnumberالمدة القصوى لأخذ عينات التدفق بالمللي ثانية.
maxResponseSizenumberالحد الأقصى لحجم الاستجابة بالبايت.
maxBufferCharsnumberحد ذاكرة التخزين المؤقت لمحلل SSE قبل حدّ الحدث؛ الافتراضي 4194304 محرفًا.
maxEventCharsnumberحد البيانات المحتفظ بها لكل حدث SSE؛ الافتراضي 1048576 محرفًا.
inheritEventIdbooleanوراثة معرّف آخر حدث SSE عند غياب المعرّف؛ الافتراضي true. اضبطه على false لاستنتاج مخطط أكثر صرامة.
onEvent(event: StreamEvent) => voidتلقي أحداث التدفق.
onConsole(log: ConsoleLog) => voidتلقي مخرجات وحدة تحكم البرامج النصية.
onAssertion(assertion: AssertionResult) => voidتلقي نتائج التحققات.
onResponseStart(info: ResponseStartInfo) => voidفحص ترويسات HTTP/SSE المبكرة وتصنيف streaming.
onOpen(info) => voidتلقي تفاصيل اتصال WebSocket: عنوان URL والبروتوكول والترويسات.

قد تفسر محولات البروتوكولات الحدود بطرق مختلفة. اجعل دوال رد النداء الخاصة بالواجهة خفيفة؛ تلتقط طبقة التنفيذ الاستثناءات التي تطرحها هذه الدوال. لإعدادات مرسل طلبات HTTP، استخدم runner.requester؛ ويجب أن تكون قيمة maxResponseSize موجبة وليست صفرًا عند تحديدها.

OperationTarget​

يحدد عملية واحدة. يُفضَّل استخدام operationId أو method + path. عند توفير الاثنين، تكون الأولوية لـ operationId.

الحقلالنوعالوصف
operationIdstringمفتاح بحث بديل له أولوية على المسار والطريقة
methodstringطريقة HTTP غير حساسة لحالة الأحرف. تتطلب path.
pathstringمسار بقالب مثل /users/{id}. يتطلب method.
// By operationId (recommended)
const result1 = await client.send({
  spec,
  target: { operationId: "getUserById" },
});

// By method + path
const result2 = await client.send({
  spec,
  target: { method: "GET", path: "/users/{id}" },
});

RequestValues​

القيم الفعلية التي تُدرج في الطلب المُنشأ.

الحقلالنوعالوصف
pathRecord<string, unknown>قيم معاملات المسار
queryRecord<string, unknown>قيم معاملات الاستعلام
headerRecord<string, unknown>قيم الترويسات
cookieRecord<string, unknown>قيم ملفات تعريف الارتباط
querystringstringسلسلة استعلام خام مرمَّزة مسبقًا؛ موضع querystring في OpenAPI 3.2
bodyunknownمحتوى الطلب
contentTypestringفرض نوع وسائط محدد للطلب عندما تعلن العملية عن عدة أنواع
const result = await client.send({
  spec,
  target: { operationId: "updateUser" },
  values: {
    path: { id: "42" },
    query: { version: "2" },
    header: { "X-Request-Id": "abc-123" },
    body: { name: "Alice", email: "alice@example.com" },
    contentType: "application/json",
  },
});

AuthConfig​

الحقلالنوعالوصف
typeAuthConfig["type"]نوع المصادقة
tokenstringرمز Bearer عند استخدام type: "bearer"
usernamestringاسم المستخدم للمصادقة Basic عند استخدام type: "basic"
passwordstringكلمة المرور للمصادقة Basic عند استخدام type: "basic"
keystringاسم مفتاح API عند استخدام type: "apikey"
valuestringقيمة مفتاح API عند استخدام type: "apikey"
in"header" | "query"موضع مفتاح API عند استخدام type: "apikey"
// Bearer token
const result1 = await client.send({
  spec,
  target: { operationId: "getUser" },
  auth: { type: "bearer", token: "your-jwt-token" },
});

// Basic auth
const result2 = await client.send({
  spec,
  target: { operationId: "getUser" },
  auth: { type: "basic", username: "admin", password: "secret" },
});

// API key in header
const result3 = await client.send({
  spec,
  target: { operationId: "getUser" },
  auth: { type: "apikey", key: "X-API-Key", value: "key-123", in: "header" },
});

تشمل أنواع المصادقة المتقدمة digest وoauth1 وoauth2 وjwt وhawk وaws4 وntlm وasap وedgegrid. مرّر حقول مساعدات Postman الخاصة بـ HTTP/SSE/GraphQL عبر parameters: Record<string, string | boolean | number>. يتيح الخيار oauth2: OAuth2FlowConfig الحصول على الرموز وتجديدها لنوع OAuth 2.0؛ لا تفترض أن كل مساعد مصادقة ينطبق على جميع البروتوكولات.

ScriptConfig​

الحقلالنوعالوصف
collectionPreRequestScriptSource | ScriptSource[]برامج نصية سابقة للطلب على مستوى المجموعة
collectionTestScriptSource | ScriptSource[]برامج اختبار على مستوى المجموعة
preRequestScriptSource | ScriptSource[]برامج نصية سابقة للطلب على مستوى الطلب
testScriptSource | ScriptSource[]برامج اختبار على مستوى الطلب
fromSpecExtensionsbooleanقراءة x-postman-scripts من المواصفة؛ الافتراضي: true
captureLastResponsebooleanإضافة مساعد مدمج يتيح للطلبات اللاحقة الوصول إلى آخر استجابة

ScriptSource:

interface ScriptSource {
  exec: string | string[];  // Script body, either a single string or array of lines
  id?: string;               // Optional identifier surfaced in script results
}

اضبط scripts.fromSpecExtensions: false إذا لم تكن تنوي تنفيذ البرامج النصية المضمّنة في مواصفة مستوردة. القيمة الافتراضية الحالية هي true؛ لا تعتمد على احتمال تغييرها مستقبلًا.

خيارات خاصة بالبروتوكولات​

HTTP / SSE​

HTTP هو المحول الافتراضي. يشير المحتوى المعلن من النوع text/event-stream إلى نية استخدام SSE؛ ويصنّف التنفيذ أيضًا الاستجابة الفعلية عند وصول الترويسات. الدالة probeStreamingResponse() فحص مستقل يُستدعى صراحةً، وليست خطوة تلقائية تسبق كل استدعاء.

لا تتطلب طلبات HTTP الأساسية إعدادات إضافية. استخدم SendOptions.runner لإعدادات postman-runtime المتقدمة.

WebSocket​

import { createManualSession } from "@powerduck/openapi-request";

const session = createManualSession({
  kind: "websocket",
  url: "wss://api.example.com/ws",
  // Manual-session options are distinct from SendOptions.websocket.
});

MCP​

import { createManualSession } from "@powerduck/openapi-request";

const session = createManualSession({
  kind: "mcp",
  endpoint: "https://api.example.com/mcp",
});

تستخدم جلسة MCP اليدوية الافتراضية Streamable HTTP وendpoint. لاستخدام stdio، مرّر kind: "mcp" وtransport: "stdio" وأمرًا محليًا في command مع args اختيارية؛ يؤدي بدء الجلسة إلى تشغيل العملية المحددة.

gRPC​

يتطلب gRPC عنوانًا ومصدرًا للواصفات، سواء ملفات .proto أو انعكاس الخادم، إضافةً إلى اسم الخدمة المؤهل بالكامل والطريقة:

import { createManualSession } from "@powerduck/openapi-request";

const session = createManualSession({
  kind: "grpc",
  address: "localhost:50051",
  service: "powerduck.examples.Echo",
  method: "Echo",
  protoPaths: ["./echo.proto"],
});

تعيد دوال إنشاء الجلسات اليدوية جلسة لم تُفتح بعد. استدعِ open() قبل الإرسال وclose() عند تحرير الموارد. يتطلب مثال gRPC خادمًا محليًا وملف proto متوافقين؛ خيارات الجلسة اليدوية ليست هي كائن SendOptions.grpc.

مثال كامل​

import { createClient } from "@powerduck/openapi-request";

const client = createClient({
  writeBack: { overwriteExamples: true },
});

const result = await client.send({
  spec: openApiDocument,
  target: { operationId: "updateUser" },
  values: {
    path: { id: "42" },
    query: { verbose: "true" },
    header: { "X-Request-Id": "req-abc" },
    body: { name: "Alice", email: "alice@example.com" },
  },
  serverUrl: "https://api.staging.example.com",
  auth: { type: "bearer", token: "staging-token" },
  timeout: 10000,
  variables: {
    environment: "staging",
  },
});

console.log(result.response.status);
console.log(result.response.body);
console.log(result.response.headers);
