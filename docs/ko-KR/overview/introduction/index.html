소개

API 구축 방식이 변화하고 있습니다. 지난 20년간 운영자는 GUI를 클릭하는 사람이었고 API 계약의 소비자는 문서를 읽는 사람이었습니다. 이제 양쪽 끝이 바뀌고 있습니다.

  • 운영자는 의도를 행동으로 바꾸는 AI 어시스턴트가 되어 가고 있습니다.
  • 소비자는 MCP를 통해 API를 도구로 호출하는 AI 에이전트가 되어 가고 있습니다.

이전 시대를 만든 도구들——API 클라이언트, 스펙 뷰어, 요청 컬렉션——은 키보드 앞의 사람을 위해 만들어졌습니다. Powerduck은 이 시대를 위해 만들어졌습니다. 그것은 더 나은 API 클라이언트도, 더 예쁜 스펙 뷰어도 아닙니다. 단일 OpenAPI 파일에서 시작하는 AI 네이티브 플랫폼입니다.

핵심: 단일 로컬 OpenAPI 파일​

모든 것은 저장소의 평범한 openapi.yaml에서 시작합니다. 개방적이고 버전 관리되며 사람과 AI 모두 읽을 수 있는 파일입니다. 독점 데이터베이스도, 클라우드 계정도 아닙니다.

                one local openapi.yaml
                         |
      you + AI -> design debug test mock docs data-model
                         |
                      MCP tools
                         |
               any AI coding agent

이 단일 파일이 계약입니다. 모든 워크플로가 여기서 읽고, 같은 파일을 MCP를 통해 어떤 AI 코딩 에이전트에든 전달할 수 있습니다. 그래서 당신과 내장 어시스턴트, 모든 외부 에이전트가 단일 신뢰 소스를 공유합니다. 설계, 디버깅, 테스트, 모킹, 문서화가 모두 같은 파일을 읽을 때, "도구 간 동기화 유지"는 더 이상 작업이 아닙니다. 그것은 목표가 아니라 설계가 낳는 결과입니다.

Powerduck은 OpenAPI 3.2를 지원하며 기존 3.0 / 3.1 문서(및 Swagger 2.0)를 즉시 업그레이드해 읽습니다. HTTP 외 API——SSE, WebSocket, GraphQL, gRPC, MCP——는 REST 전용 형태로 강제 변환되지 않고 x-protocol 확장을 통해 일반 경로 항목으로 모델링됩니다.

AI와 함께 일하는 방식​

  • YAML을 열면 어시스턴트가 즉시 그것으로 할 수 있는 일을 제안합니다.
  • "주문 엔드포인트 만들어줘", "테스트 데이터 준비해줘", "결제 플로우 실행하고 보고서 만들어줘"처럼 평범한 말로 결과를 말하면 어시스턴트가 적절한 도구를 선택하고 변경을 제안합니다.
  • 모든 변경은 검토 가능한 카드로 도착합니다. 당신이 승인하기 전에는 아무것도 적용되지 않습니다.
  • 어떤 API를 refine할 때 어시스턴트는 그 API에 머물며 요청한 부분만 변경하고 문서 전체로 흐트러지지 않습니다.
  • OpenAI 호환 모델을 무엇이든 가져올 수 있습니다. 데스크톱에서는 프롬프트와 키가 머신 밖으로 나가지 않습니다.

기본은 로컬 우선​

Powerduck은 당신의 머신에서 실행되고, 실제 파일을 열어 저장하며, 오프라인으로 동작하고, API 키와 프롬프트를 브라우저에서 멀리 둡니다. 클라우드는 공유와 게시를 위한 선택적 확장이며, 시작하기 위한 전제가 아닙니다.

Powerduck을 사용하는 3가지 방법​

형태그것은 무엇인가적합한 상황
데스크톱 클라이언트AI 어시스턴트와 완전한 API 워크스페이스를 갖춘 로컬 우선 Electron 앱모든 것을 자신의 머신에 두고 오프라인으로 작업하며 키와 프롬프트를 로컬에 유지하려는 엔지니어
Powerduck CloudOAS 호스팅, 온라인 문서, 관리형 MCP를 위한 호스팅 서비스API를 다른 사람과 공유하고 안정적인 링크를 게시하며 아무것도 실행하지 않고 MCP를 제공하려는 경우
오픈소스 라이브러리조합 가능한 @powerduck/* npm 패키지자체 도구, CI 파이프라인, 임베디드 컴포넌트를 구축하는 경우

세 형태는 같은 엔진을 공유합니다. 데스크톱 클라이언트와 클라우드는 모두 오픈소스 라이브러리로 조립되어, 로컬에서 실행하든 네트워크로 호출하든 패키지를 직접 import하든 기능이 동일하게 동작합니다.

데스크톱 클라이언트​

데스크톱 클라이언트는 완전히 당신의 머신에서 실행됩니다. 디스크의 실제 파일을 열어 편집하고, 로컬 프로세스로 요청을 보내며, 로컬 모크를 실행하고, AI 프롬프트와 API 키를 브라우저 콘솔에서 멀리 둡니다. 모델은 자유롭게 구성할 수 있고, 제안된 변경은 적용 전 검토 가능한 카드로 도착합니다.

Powerduck Cloud​

Powerduck Cloud는 같은 워크플로를 온라인으로 가져옵니다. 파일, Git 저장소, URL을 추가하고 노출할 작업을 선택하면 렌더링된 문서의 안정 링크와 관리형 MCP 엔드포인트를 얻습니다. 접근은 보기 비밀번호나 MCP 접근 키로 보호할 수 있으며, 유료 플랜에서는 Git 동기화, 사용자 지정 도메인, 더 높은 한도가 추가됩니다.

오픈소스 라이브러리​

라이브러리는 그 아래에서 동작하는 엔진입니다. OpenAPI 파서와 업그레이더, 멀티프로토콜 CLI, 코드 생성기, MCP 서버, 요청 러너, cURL / Postman 변환기, 임베디드 에디터가 있습니다. 각각 독립적으로 npm에 게시되고 전용 설치 가이드와 API 참조를 갖습니다. 저수준 기술 세부 사항은 여기에 있습니다.

당신에게 달라지는 것​

  • 클릭이 아니라 결과를 지시합니다. 목표를 말하면 어시스턴트가 검토 가능한 단계로 작업을 진행합니다.
  • API가 처음부터 에이전트 지원이 됩니다. 문서를 생성하는 같은 계약이 MCP 도구도 생성해, AI 에이전트가 첫날부터 올바르게 API를 호출할 수 있습니다.
  • 흐트러짐이 없습니다. 설계, 디버깅, 테스트, 모킹, 문서화가 단일 파일을 읽습니다.
  • 모든 프로토콜이 한 곳에. HTTP, SSE, WebSocket, GraphQL, gRPC, MCP가 6개 도구가 아닌 단일 스펙에 포함됩니다.
  • 락인 없음. 모델을 가져오고, 데스크톱에서 키를 로컬에 두며, 저장소의 평문 YAML을 소유할 수 있습니다.

다음으로 갈 곳​

  • 처음이신가요? 설치와 빠른 시작으로 시작하세요.
  • 완전한 로컬 워크스페이스가 필요한가요? 데스크톱 클라이언트 가이드를 읽으세요.
  • API를 온라인으로 게시하고 싶은가요? Cloud 가이드를 읽으세요.
  • 자체 통합을 구축하고 있나요? 오픈소스 라이브러리를 보세요.
