@powerduck/conf-patch

@powerduck/conf-patch 是采用清晰双层架构的配置编辑库。它遵循 RFC 6902 JSON Patch 语义修改 JSON、JSONC 和 YAML 字符串，保留注释与格式，并为 Node.js 和 Electron 提供原子写入和跨进程文件锁。

  • 版本：
  • 许可证： MIT
  • Node.js 要求： >= 22.12.0
  • 源码： github.com/powerducklab/conf-patch

为什么选择 conf-patch？​

通过代码修改配置文件，往往需要在两种方案间取舍：重新序列化整个文档可能改变注释、空白和格式，手工操作文本又容易出错。conf-patch 提供：

  • 保留注释的增量修改： JSON/JSONC 使用 jsonc-parser，YAML 使用 yaml 修改 AST。JSON/JSONC 无需整体重新序列化；YAML 则重新序列化修改后的 AST。
  • 原子写入： 先写入临时文件再重命名，避免目标文件只写入一部分。
  • 跨进程文件锁： 支持所有权令牌、指数退避重试和过期锁恢复。
  • 适用于多种环境的 API： 核心层可在浏览器、边缘函数和使用 IndexedDB 存储的应用中运行。

双层架构​

┌──────────────────────────────────────────────────────────────┐
│                     Application code                          │
├──────────────────────────────────────────────────────────────┤
│  File layer (Node.js / Electron only)                         │
│  ┌───────────────┐ ┌────────────────┐ ┌──────────────────┐  │
│  │ readConfigFile │ │ writeConfigFile│ │ patchConfigFile   │  │
│  │ setConfigValue │ │ deleteConfig…  │ │ withFileLock     │  │
│  └──────┬────────┘ └───────┬────────┘ └────────┬─────────┘  │
│         │                  │                   │            │
│  ┌──────▼──────────────────▼───────────────────▼───────────┐ │
│  │           Core layer (browser-safe, zero Node deps)      │ │
│  │  patchContent   setContentValue   deleteContentValue     │ │
│  └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘

核心层 — @powerduck/conf-patch/core（兼容浏览器）​

操作字符串的纯函数，不依赖 node:fs、node:path 或其他 Node.js 专用 API。此子路径导出可打包到浏览器、边缘函数或 Service Worker 代码中。

函数用途
patchContent对配置字符串应用一组 RFC 6902 操作
setContentValue设置或创建嵌套值（使用 add）
deleteContentValue删除键或数组元素（使用 remove）

文件层 — @powerduck/conf-patch（Node.js / Electron）​

读写实际文件的异步函数，在核心层之上提供原子写入和锁机制。

函数用途
readConfigFile从文件路径或 file:// URL 读取 UTF-8 文本
writeConfigFile原子写入内容，可选择加锁
patchConfigFile在文件锁内执行读取、修改、写入事务
setConfigValue设置文件中的嵌套值
deleteConfigValue删除文件中的嵌套值
withFileLock在独占锁保护下执行任务
releaseAllLocalLocks释放当前进程持有的所有锁

支持的格式​

格式扩展名行为
JSON.json标准 JSON，通过 jsonc-parser 增量修改。
JSONC.jsonc支持注释和尾随逗号的 JSON，保留注释。
YAML.yaml, .ymlYAML 1.2，通过 AST 修改保留注释、锚点和缩进。

detectFormat 将文件扩展名映射到 ConfigFormat。其他扩展名会触发错误，除非显式传入 format。

RFC 6902 操作​

conf-patch 实现 RFC 6902 的一个子集，仅支持以下操作：

op行为
"add"在数组索引处插入，或添加、替换对象属性
"replace"替换已有值，路径必须存在
"remove"删除已有键或数组元素，路径必须存在
警告

不支持 "move"、"copy" 和 "test"。JsonPatchOp 类型将 op 限定为 "add" | "replace" | "remove"。

行为说明：

  • 对数组索引执行 add 会插入元素（RFC 6902）。要替换已有元素，请使用 replace。
  • add 要求父路径已存在；请先创建父节点，再创建子节点。
  • replace 和 remove 要求目标路径已存在。
  • 设置 strict: true（默认值）时，操作失败会抛出异常；设置 strict: false 时，会跳过失败操作并记录警告。

保留注释与格式​

  • JSON/JSONC： 根据语法树计算需要修改的文本区间，保留周围的注释、尾随逗号和缩进。
  • YAML： 原地修改 yaml AST 后重新序列化，保留注释、锚点、别名和缩进。

OpenAPI 校验​

conf-patch 对 @powerduck/openapi-parser 进行安全封装，用于校验 OpenAPI/Swagger 文档：

  • validateOpenAPISpec 校验原始 JSON 或 YAML 内容。
  • validateOpenAPIFile 根据文件路径校验文档。
  • 输入处理涵盖大小限制、路径沙箱（allowedRootDirectory）、结构复杂度检查、超时控制和 AbortSignal 取消。
  • 失败时抛出 OpenApiValidationError，包含可供程序识别的 code。
