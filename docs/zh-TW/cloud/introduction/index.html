Powerduck Cloud

Powerduck Cloud 讓一份 OpenAPI 檔案變成你可以分享的東西。新增一份規範，選擇暴露什麼，把渲染文件和託管 MCP 伺服器的穩定連結交給別人——無需自己託管或執行任何程式。

它與桌面用戶端是同樣的合約優先、AI 輔助工作流，只是為團隊和消費者搬到了線上。

旅程​

  1. 新增一份規範，可以上傳檔案、指向 Git 儲存庫或貼上 URL。你甚至可以在官網開始流程，準備好時再登入——不必上傳兩次。
  2. 選擇暴露什麼。 單獨開啟或關閉各個操作；你的原始檔案從不會被修改。
  3. 立即打開文件連結——渲染的 API 文件預設開啟。託管 MCP 端點只差一個開關，在你選擇向代理暴露工具之前保持關閉。
  4. 控制存取。 新增文件檢視密碼和有效期，以及給代理的獨立 MCP 存取密鑰。
  5. 發布並分享。 為當前版本發布一個就緒產物，讓連結可解析；進階控制一鍵可達。
  6. 保持最新。 每次變更建立一個新版本，可對比或回滾，Git 來源可在更新時同步。
  7. 管理生命週期。 暫停、恢復或歸檔文件；一眼檢視其狀態、版本和來源。

你會得到什麼​

  • 穩定的文件連結，在你發布新版本時仍保持可讀；
  • 託管 MCP 端點，讓他人的 AI 代理能夠發現並呼叫你選擇的操作；
  • 按操作暴露，讓內部或未完成的介面不進入公開面；
  • 存取控制，含檢視密碼、有效期和 MCP 存取密鑰；
  • 版本歷史，含對比和回滾——原始內容從不會被覆蓋；
  • Git 同步，讓儲存庫更新流入新的託管版本；
  • 自訂網域，包括子路徑配置，帶來品牌化體驗。

一份文件，多個版本​

每次編輯建立新版本而非覆蓋原始內容，因此你可以對比版本、回滾，並針對已知狀態重新發布文件和 MCP。文件和 MCP 始終綁定到特定文件和版本，從不會指向模糊的「最新」。

為什麼連結可能打不開​

當三件事齊備時，文件或 MCP 連結才可解析，文件工作區會展示每一項，並高亮第一個未滿足的要求：

  1. 文件處於活動狀態——暫停它會讓文件和 MCP 一起下線；
  2. 你分享的形態已啟用——文件和 MCP 各有自己的開關（文件預設開啟，MCP 預設關閉）；
  3. 當前產物已發布——在你新增版本或變更暴露操作後它會自動建構，因此通常你無需操作；手動發布作為兜底可用。

存取檢查——檢視密碼、有效期或 MCP 存取密鑰——在這三者之上生效。

登入與歸屬​

用 Google 或 GitHub 登入。OAuth 握手之後，Powerduck 以安全、HttpOnly 的 Cookie 簽發自己的工作階段——服務商的權杖從不會用作你的長期身分。一切都歸屬於一個組織；個人組織會自動建立，團隊以後可以共享一個而無需重新設計。

主控台​

  • Dashboard（儀表板）——新增規範，檢視最近文件及快速連結和起停動作；
  • Projects（專案）——組織文件；
  • 文件工作區——狀態、文件、MCP、暴露操作、版本、來源和網域，分清晰、帶標籤的區塊；
  • Billing（帳單）——訂閱狀態和訂單，保持分開；
  • Hub——發布並瀏覽公開文件和 MCP 伺服器；
  • **Settings（設定）**和 Activity（活動）——個人資料、偏好和稽核日誌。

公開讀者使用專門的文件檢視器，除非文件要求密碼，否則無需帳號。
