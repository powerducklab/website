API 參考

@powerduck/openapi-request 主要整合 API 的參考文件。表格概述介面約定；完整的多載與選用參數以套件內 TypeScript 宣告為準。主入口和協定子路徑匯出的內容並不完全相同。

核心 API​

createClient(options?): ProtoClient​

建立以 UI 為導向的用戶端。options 參數可省略。

參數：

名稱型別說明
optionsCreateClientOptions選用設定
options.writeBackWriteBackOptions控制回應如何合併回規格
options.responseToResponseOptions控制回應物件的正規化方式

傳回： 包含以下方法的 ProtoClient：

方法簽章說明
prepare(sendOptions: SendOptions) => PreparedRequest規劃請求，傳回協定、顯示模式和串流類型
send(sendOptions: SendOptions) => Promise<SendResult>執行請求
sendMany(spec, targets, shared?) => Promise<SendManyResult>批次執行，分別傳回各目標的結果；單一失敗不會捨棄其他結果
connect(connectOptions: ManualSessionOptions) => AnyManualSession建立尚未開啟的 websocket/mcp/grpc 工作階段；呼叫 open() 建立連線
discover(discoverOptions) => Promise<any>探索 MCP 和 gRPC 的能力
writeback(spec, prepared, result, writeOptions?) => OpenApiDocument將觀察到的回應合併回文件
dispose() => void目前不執行任何操作；呼叫端必須自行關閉工作階段
probeStreamingResponse(input: RequestInfo | URL, init?: RequestInit) => Promise<{ ok: boolean; status: number; contentType?: string; kind: "none" | "sse" | "ndjson" | "chunked"; response: Response }>執行 fetch 請求並分類回應；需讀取或取消傳回的回應主體

範例：

import { createClient } from "@powerduck/openapi-request";

const client = createClient({
  writeBack: { overwriteExamples: true },
});

const plan = client.prepare({
  spec,
  target: { operationId: "getUserById" },
});

const result = await client.send({
  spec,
  target: { operationId: "getUserById" },
  values: { path: { id: "42" } },
});

createDebugger(config?): ProtoKit​

建立用於自動化、指令碼和 CI 的指令碼式偵錯器。

參數：

名稱型別說明
configDebuggerOptions選用設定
config.adaptersProtocolAdapter[]自訂介接器清單，取代預設介接器
config.extraAdaptersProtocolAdapter[]加入預設清單的額外介接器
config.writeBackWriteBackOptions回寫選項
config.responseToResponseOptions回應正規化選項
config.writeBackTruncatedboolean回寫從截斷串流推斷出的 Schema（預設：true）

傳回： 包含 prepare、send、sendMany、toCollection 等方法的 ProtoKit。

範例：

import { createDebugger } from "@powerduck/openapi-request";

const dbg = createDebugger({
  writeBackTruncated: true,
});

const result = await dbg.send({
  spec,
  target: { operationId: "getUserById" },
  values: { path: { id: "42" } },
  serverUrl: "https://api.example.com",
});

createManualSession(options): AnyManualSession​

建立 WebSocket、MCP 或 gRPC 的長期雙工工作階段。建立函式本身不執行 I/O；呼叫 open() 後才建立連線。

參數：

名稱型別說明
options.kind"websocket" | "mcp" | "grpc"要使用的協定
options.urlstringWebSocket 連線 URL
options.endpointstringMCP Streamable HTTP 端點
options.transport"streamable-http" | "stdio"MCP 傳輸方式，預設使用 Streamable HTTP
options.command, options.argsstring, string[]MCP stdio 的本機可執行檔與參數
options.address, options.service, options.methodstringgRPC 位址、完整限定的服務名稱與方法

gRPC 還需透過 protoPaths 或 reflection 提供描述元來源。各協定的選項見設定。

傳回： 具有 open()、send()、close()、onEvent()、waitForClose()、events 和 state 的工作階段。onEvent() 會傳回具有 unsubscribe() 的訂閱物件。

範例：

import { createManualSession } from "@powerduck/openapi-request";

const session = createManualSession({
  kind: "websocket",
  url: "wss://api.example.com/ws",
});

const subscription = session.onEvent((event) => {
  console.log(event.kind, event.data);
});
try {
  await session.open();
  await session.send({ type: "message", data: "hello" });
} finally {
  await session.close();
  subscription.unsubscribe();
}

AdapterRegistry​

用於管理 ProtocolAdapter 執行個體的登錄表。新建登錄表為空；除非傳入自訂清單取代，否則 createDebugger() 會註冊內建 HTTP、WebSocket、gRPC、MCP 和 GraphQL 介接器。可透過 register()、unregister()、get()、list()、rank() 和 resolve() 管理選擇流程。

ProtoKitError​

偵錯器及核心執行路徑拋出的具型別錯誤。使用 instanceof ProtoKitError 區分函式庫錯誤與其他非預期故障。

核心型別​

SendOptions​

prepare() 與 send() 的主要輸入物件，用於傳入規格、目標、具體值與所有請求層級設定。

欄位型別必填說明
specOpenApiDocument是完整的 OpenAPI 3.2 文件
targetOperationTarget是操作識別資訊，詳見下文
valuesRequestValues否path/query/header/cookie/body 的具體值
serverUrlstring否覆寫 spec.servers[0].url
serverVariablesRecord<string, string>否伺服器 URL 範本變數
variablesRecord<string, string>否以 {{name}} 參照的環境變數
globalsRecord<string, string>否Postman 風格的全域變數
localVariablesRecord<string, string>否區域變數
collectionVariablesRecord<string, string>否集合層級變數
authAuthConfig否驗證設定
scriptsScriptConfig否請求前與測試指令碼
runnerRuntimeRunOptions否完整傳遞 postman-runtime 選項，優先順序最高
websocketWebSocketOptions否WebSocket 專用選項
graphqlGraphQLOptions否GraphQL 專用選項
mcpMcpOptions否MCP 專用選項
grpcany否gRPC 專用選項
timeoutnumber否每次請求的逾時時間，單位毫秒，是 runner.timeout.request 的簡便寫法

SendOptions 也接受以下執行與串流控制選項：

欄位型別說明
fetchtypeof fetch在支援的情境下使用宿主提供的隔離 fetch 傳輸；HTTP/SSE 仍使用 postman-runtime。
writeBackboolean設為 false 時不產生 patchedSpec，但仍會產生 responseFragment。
signalAbortSignal取消執行或取樣，仍可能回傳部分結果。
maxEventsnumber最多保留的串流事件數量。
maxStreamMsnumber串流取樣的最長時間，單位毫秒。
maxResponseSizenumber回應位元組數上限。
maxBufferCharsnumberSSE 解析器在事件邊界前的緩衝上限，預設 4194304 個字元。
maxEventCharsnumber每個 SSE 事件保留的資料上限，預設 1048576 個字元。
inheritEventIdboolean缺少 ID 時繼承上一個 SSE 事件 ID，預設 true。如需更嚴格的結構描述推斷，請設為 false。
onEvent(event: StreamEvent) => void接收串流事件。
onConsole(log: ConsoleLog) => void接收指令碼主控台輸出。
onAssertion(assertion: AssertionResult) => void接收斷言結果。
onResponseStart(info: ResponseStartInfo) => void取得早期 HTTP/SSE 標頭與 streaming 分類。
onOpen(info) => void接收 WebSocket 連線詳情：URL、協定與標頭。

各協定配接器對限制的解讀可能不同。UI 回呼應保持輕量；執行層會捕捉回呼擲出的例外。HTTP 請求器設定使用 runner.requester；若指定其中的 maxResponseSize，必須為正數，不能為零。

OperationTarget​

識別單一操作。建議擇一使用 operationId 或 method + path；若兩者都提供，以 operationId 優先。

欄位型別說明
operationIdstring另一種查找鍵，優先於路徑與方法
methodstringHTTP 方法，不區分大小寫；須同時提供 path。
pathstring範本路徑，例如 /users/{id}；須同時提供 method。

RequestValues​

注入產生之請求的具體值。

欄位型別說明
pathRecord<string, unknown>路徑參數值
queryRecord<string, unknown>查詢參數值
headerRecord<string, unknown>標頭值
cookieRecord<string, unknown>Cookie 值
querystringstring原始且已編碼的查詢字串，適用於 OpenAPI 3.2 的 querystring 位置
bodyunknown請求本文
contentTypestring操作宣告多個媒體型別時，強制指定請求媒體型別
const result = await client.send({
  spec,
  target: { operationId: "updateUser" },
  values: {
    path: { id: "42" },
    query: { version: "2" },
    header: { "X-Request-Id": "abc-123" },
    body: { name: "Alice", email: "alice@example.com" },
    contentType: "application/json",
  },
});

AuthConfig​

欄位型別說明
typeAuthConfig["type"]驗證類型
tokenstringBearer 權杖，適用於 type: "bearer"
usernamestringBasic 驗證使用者名稱，適用於 type: "basic"
passwordstringBasic 驗證密碼，適用於 type: "basic"
keystringAPI 金鑰名稱，適用於 type: "apikey"
valuestringAPI 金鑰值，適用於 type: "apikey"
in"header" | "query"API 金鑰位置，適用於 type: "apikey"
// Bearer token
const result1 = await client.send({
  spec,
  target: { operationId: "getUser" },
  auth: { type: "bearer", token: "your-jwt-token" },
});

// Basic auth
const result2 = await client.send({
  spec,
  target: { operationId: "getUser" },
  auth: { type: "basic", username: "admin", password: "secret" },
});

// API key in header
const result3 = await client.send({
  spec,
  target: { operationId: "getUser" },
  auth: { type: "apikey", key: "X-API-Key", value: "key-123", in: "header" },
});

進階驗證類型包括 digest、oauth1、oauth2、jwt、hawk、aws4、ntlm、asap 與 edgegrid。透過 parameters: Record<string, string | boolean | number> 傳遞其在 HTTP/SSE/GraphQL 中使用的 Postman 輔助欄位。選用的 oauth2: OAuth2FlowConfig 為 OAuth 2.0 啟用權杖取得與更新；請勿假設每種驗證輔助方式都適用於所有協定。

PreparedRequest​

由 createClient().prepare() 傳回。偵錯器的規劃結果不同：createDebugger().prepare() 會傳回包含 located、adapter 和 plan 的 PlanResult。

欄位型別說明
protocolstring解析出的協定（http、websocket、grpc、graphql、mcp）
transportstring解析出的傳輸方式
targetOperationTarget原始目標
operationany解析出的 OpenAPI 操作物件
display.modeDisplayMode"response" | "event-list" | "duplex-session"
stream.kindStreamKind串流分類（見下文）
stream.expectedboolean是否預期為串流回應
openapi.extensionsRecord<string, unknown>解析出的 OpenAPI 擴充
warningsstring[]規劃過程中出現的警告

StreamKind​

完整的串流類型分類："none" | "sse" | "ndjson" | "chunked" | "websocket" | "graphql-stream" | "grpc-unary" | "grpc-server-stream" | "grpc-client-stream" | "grpc-bidi" | "mcp-http-stream" | "mcp-stdio"

OpenAPI 輔助函式​

匯出項目簽章說明
locateOperation(spec, target) => LocatedOperation透過 OperationTarget 解析操作
inferSchema(value) => Schema從單一觀察值推斷 JSON Schema
inferSchemaFromMany(values) => Schema推斷涵蓋多個觀察值的 Schema
mergeSchema(a, b) => Schema合併兩個推斷出的 Schema（聯集或組合）
sampleFromSchema(schema) => unknown為 Schema 產生貼近實際的範例值
toResponseObject(result, options?) => { statusCode: string; response: any }從觀察結果建立 OpenAPI 回應物件
writeBackResponse(spec, path, method, fragment, options?) => spec將觀察到的回應合併回文件

匯出的型別：LocatedOperation、WriteBackOptions、ToResponseOptions。

HTTP / SSE​

以下名稱可從主入口匯入。@powerduck/openapi-request/http 子路徑匯出 HttpAdapter、SseParser、buildCollection、buildEnvironment、resolveServerUrl、buildRunOptions 和 runWithPostman；偵測輔助函式和 BUILTIN_CAPTURE_TEST 請從主入口匯入。

匯出項目說明
HttpAdapterHTTP/HTTPS 的預設協定介接器
SseParser將 SSE 位元組串流轉換為結構化事件的串流解析器
isStreamingOperation依宣告的內容類型判斷操作是否採用串流
isSseContentType判斷內容類型是否表示 SSE
isStreamingContentType判斷內容類型是否表示串流
acceptHeaderFor為操作產生適當的 Accept 請求標頭
probeStreamingResponse執行 fetch 請求並分類回應；需讀取或取消傳回的回應主體
BUILTIN_CAPTURE_TEST用於擷取最後一次回應的內建 Postman 測試指令碼

WebSocket​

從 @powerduck/openapi-request/ws 匯入。

匯出項目說明
WebSocketAdapterWebSocket 目標的協定介接器
createWsManualSession建立雙工 WebSocket 手動工作階段，別名為 runWebSocketSession、wsManualSession

GraphQL​

從 @powerduck/openapi-request/graphql 匯入。

匯出項目說明
GraphQLAdapterGraphQL 目標的協定介接器
resolveGraphQLConfig從操作解析 GraphQL 設定
runGraphQL執行 GraphQL 操作
introspectSchema內省 GraphQL 端點的 Schema
INTROSPECTION_QUERY標準 GraphQL 內省查詢
generateOperation從內省得到的 GraphQL Schema 與欄位產生查詢文件
generateAllOperations為內省得到的 GraphQL Schema 各欄位產生查詢文件
writeGraphQLOperations將產生的 GraphQL 操作回寫到規範
discoverAndWriteGraphQLSchema探索 GraphQL Schema 並寫入規範

MCP（模型上下文協定）​

下列大多數項目可從 @powerduck/openapi-request/mcp 匯入。initializeMcpSession 從主入口匯入，其在子路徑中的名稱是 initializeSession。子路徑還匯出 runMcp、createMcpSessionCore 和 createMcpStdioConnection。

匯出項目說明
McpAdapterMCP 目標的協定介接器
createMcpManualSession建立 MCP 手動工作階段，別名為 mcpManualSession
createMcpStdioSession建立透過 stdio 的 MCP 工作階段
runMcpManualSession已棄用，請使用 createMcpManualSession
resolveMcpConfig從操作解析 MCP 設定
initializeMcpSession初始化 MCP 工作階段，原名為 initializeSession
discoverMcpCapabilities探索 MCP 伺服器能力
MCP_PROTOCOL_VERSION支援的 MCP 協定版本
generateMcpCall產生單一 MCP 工具呼叫
generateAllMcpCalls產生所有 MCP 工具呼叫
writeMcpOperations將 MCP 操作回寫到規範
discoverAndWriteMcpCapabilities探索 MCP 能力並寫入規範
createHttpMcpTransport建立 MCP 的 HTTP 傳輸
createStdioMcpTransport建立 MCP 的 stdio 傳輸

gRPC​

從 @powerduck/openapi-request/grpc 匯入底層探索、呼叫和描述元輔助函式。GrpcProtocolAdapter、createGrpcManualSession、grpcManualSession、grpcDiscover 和 discoverGrpc 從主入口匯入；子路徑中的探索函式名為 discover。子路徑還提供 discoverFromCatalog、describeMethod 和 describeFromCatalog，可重複使用服務目錄，避免為每個方法重複反射。

匯出項目說明
GrpcProtocolAdapter面向 OpenAPI 的 gRPC 協定介接器
GrpcAdapter底層 gRPC 介接器
grpcDiscover / discoverGrpc探索 gRPC 服務與方法
createGrpcManualSession / grpcManualSession建立 gRPC 手動工作階段
grpcCall執行一次 gRPC 呼叫
resolveMethod解析 gRPC 方法描述元
buildMessageTemplate從描述元建立訊息範本
buildCatalog建立服務與方法目錄
LOADER_OPTIONS預設 proto 載入器選項
scanProtoFiles掃描目錄中的 proto 檔案
deriveIncludeDirsDetailed從 proto 檔案路徑推導包含目錄
fetchDescriptorSet透過 gRPC 反射取得描述元集
fetchFullDescriptorSet取得包含所有相依項目的完整描述元集
listServices列出描述元集中的服務
listServicesDetailed列出服務及詳細方法資訊
serializeDescriptorSet將描述元集序列化為位元組
decodeFileDescriptorProto解碼單一檔案描述元 proto
decodeFileDescriptorSet解碼檔案描述元集
buildCredentials建立 gRPC 認證資料（同步）
buildCredentialsAsync建立 gRPC 認證資料（非同步）
buildCredentialsChecked驗證並建立認證資料（同步）
buildCredentialsCheckedAsync驗證並建立認證資料（非同步）
loadGrpc動態載入 @grpc/grpc-js 套件
isGrpcAvailable檢查 gRPC 相依套件是否可用
requireCapability要求指定 gRPC 能力，無法使用時拋出錯誤

主入口匯出型別別名 GrpcDiscoveryResult、GrpcDiscoveredMethod 和 GrpcDiscoveredService。gRPC 子路徑中的對應名稱為 DiscoveryResult、DiscoveredMethod 和 DiscoveredService。

錯誤型別：ReflectionProtocolError、ReflectionUnavailableError、DescriptorDecodeError、GrpcDependencyBrokenError、GrpcDependencyMissingError。

其他工具​

主入口還匯出 OAuth 2.0 輔助函式 resolveOAuth2Token、acquireOAuth2Token、isOAuth2TokenExpired、oauth2RefreshStatuses 和 authFromOAuth2Token；複製工具 toCloneable；基底類別 UnifiedSession；以及 gRPC 回寫輔助函式 writeGrpcOperations 和 discoverAndWriteGrpcOperations。
